# MT7902 native Wi-Fi in MtkWlan 0.13.1

This fork integrates our MT7902 Connac2 adaptation of hbyonly1/itlmt7922-wifi,
snapshot commit `a4869dfc513f1a4ac2bc802657ba1854ad4aaaa8` (0.2.12), into MtkWlan. It includes
the WTLWifiMenu native frontend, pinned at commit
`a768120b0477930357289dcdfed45a34ec60673d`, with the local changes recorded in
NOTICE.md. The MT7925 Connac3 backend stays separate.

**This integrated build has not been tested on MT7902 hardware.** The original
0.2.11 driver connected to Android and iPhone hotspots in user testing. The 0.2.12
HT20 router compatibility changes, native bridge, private MAC handling and the
new package remain unverified on hardware. CI success does not establish that
your router will connect.

## Native installation

1. Keep your working EFI and hotspot-capable driver as a recovery copy.
2. Disable/remove `itlmt7902.kext` from OpenCore's Kernel/Add list. Install this
   package's **MtkWlan.kext**, followed by **MtkWlanNative.kext**, in
   `EFI/OC/Kexts`, and add both with your existing OpenCore snapshot tool.
   Their ExecutablePaths are `Contents/MacOS/MtkWlan` and
   `Contents/MacOS/MtkWlanNative`; each uses `Contents/Info.plist`.
   Load exactly one PCI driver for this card.
3. Native mode and the native interface are enabled by default in this package.
   No `mt7902_stage=3`, `mtkfe=native`, or `mtknativeif=1` arguments are required.
   Remove older `mt7902_stage=0/1/2`, `mtkfe=ethernet`, `mtknative=0` or
   `mtknativeif=0` overrides if present. Other diagnostic arguments still work.
4. Quit the old ItlWiFi7902 app and disable its login item. Boot once to load the
   new kexts. Use **macOS's Wi-Fi menu/System Settings** to scan, enter the
   password, join and manage saved networks. The included app is optional and
   is only for the Ethernet fallback, not required for native Wi-Fi.

The native frontend preserves upstream's private Apple ABI checks. It supports
Tahoe **26.7.1 (25G241)** and **26.7.2 (25G332)** only, checking both the running
XNU version and live class sizes. “Latest Tahoe” does not identify the exact build;
`sw_vers -productVersion; sw_vers -buildVersion` does. Do not bypass the guard.
For another build, a kernel-collection ABI dump and verified headers are required;
see `native/WTLWifiMenu/tools/kcabi/README.md`.

If the native frontend declines or never binds, MtkWlan falls back to an Ethernet
interface (up to 15 seconds without a claim, 90 seconds after a claim). The native
decline reason is published in `MtkNativeDeclined`. Changing networks after boot
does not require another reboot.

## Optional Ethernet mode

To select Ethernet explicitly, use `mtkfe=ethernet` or change the MT7902
personality's `MtkFrontEnd` to `ethernet` before boot. The native frontend respects
that choice. Use **MtkWiFi7902.app** from this package or:

```sh
./mtkwifi status
sudo ./mtkwifi scan --wait
sudo ./mtkwifi join "Your SSID" --ask
sudo ./mtkwifi disconnect
```

The menu app derives the WPA2 PMK in userspace and sends the Mtk userspace API
request. Passwords are never placed in Info.plist or passed on a command line.
The MT7902 personality explicitly permits the logged-in console user to scan,
join and disconnect, matching the old app. Set `MtkAllowConsoleControl` false for
administrator-only control. MT7925's administrator policy is unchanged. When the
native interface owns the radio, legacy user-client join/disconnect is refused.

## Architecture

MtkWlan selects MT7902 by PCI 14c3:7902 before any Connac3 MMIO, DMA or firmware.
The Connac2 worker owns all hardware rings, firmware commands and WPA2 state.
Bounded 64-packet RX/TX queues cross to the Mtk work loop. All frontend callbacks
run on the core's gate, with no backend lock held. Delayed TX completions cannot
consume packets queued after a disconnect flush. The core publishes its service
only after the firmware's station MAC is available, so the native frontend starts
with the correct address.

The native API includes full beacon information elements, signal/channel/security
snapshots, scan and join completion callbacks, the BSSID selected by macOS, link
state and Ethernet frame delivery through Skywalk. The native frontend submits private MAC intent through the explicit
`mtk-queue-mac-v1` extension. No native/BSD/core gate waits for firmware. A queued
join and its PMK stay in their mailbox until the worker confirms DEV_INFO; TX is
also blocked during the address transition. Failure restores the old address,
fails the deferred join and disconnects. Strict core API v4 set_mac refuses an
unapplied change instead of falsely reporting synchronous completion. The chosen
address is restored during firmware recovery. Native extended BSS
reporting uses the negotiated HT stream count and does not claim VHT for MT7902.

Both chips' firmware is embedded in MtkWlan.kext. CI verifies pinned SHA-256 values
and confirms each complete blob occurs exactly once in the executable. No external
firmware directory is required. Both upstream projects' license notices ship in
the package. Mtk core API v1/v2/v3/v4 is implemented for MT7902; v5 country/rate
operations remain unavailable. The native frontend accepts v4.

## Remaining limits and validation

Only visible WPA2-PSK/CCMP networks with optional PMF are joinable. No open, WEP,
WPA3-only, enterprise, required-PMF, DFS or 6 GHz joins. Supported join channels
are 1–11, 36/40/44/48 and 149/153/157/161/165. Embedded-NUL SSIDs and multicast
BSSIDs are rejected. The backend keeps the existing 10 dBm test ceiling,
single-stream HT20/legacy profiles and legacy fallback. Off-channel scans while
connected return the cache through the native frontend. Group rekey, sleep/wake,
roaming, AWDL/AirDrop and router interoperability remain unfinished.

Run `bash collect-logs.sh` after a failed attempt. It captures MtkWlan, the native
and Ethernet interfaces, and mirrored backend diagnostics. Hardware validation
needs native scan/password entry, the requested BSSID and private address on air,
WPA2 handshake, DHCP, DNS, IPv4/IPv6 traffic, disconnect/rejoin, firmware recovery
and sustained traffic on both the known-working hotspot and the router.

## 0.13.1 freeze investigation

The user reported an OS freeze when joining through 0.13.0/0.4.16 on 25G332.
The supplied snapshot confirms firmware/scan/private-MAC registration succeeded,
but contains no authentication attempt or native-interface trace/backtrace.
0.13.1 removes the blocking private-MAC wait on the core gate and holds joins
behind worker confirmation. This addresses a blocking path; the cause of the
reported full-system freeze is not proven by that snapshot. Hardware retesting
is still required. Replace both kexts as a pair (native 0.4.17 requires core 0.13.1).

To restore the old known-working hotspot path, disable both new kexts in OpenCore
and restore the previous itlmt7902.kext with its matching ItlWiFi7902 app. To use
this core's Ethernet fallback instead, select mtkfe=ethernet and use the included
MtkWiFi7902.app. The old ItlWiFi7902 app cannot control the MtkWlan user client.
Native ownership deliberately refuses app join/disconnect requests.
