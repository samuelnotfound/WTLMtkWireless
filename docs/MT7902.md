# MT7902 in MtkWlan 0.13.0

This fork integrates the MT7902 Connac2 backend from samuelnotfound/itlwm commit
`a4869dfc513f1a4ac2bc802657ba1854ad4aaaa8` (0.2.12) into the MtkWlan service,
MtkWlanEth interface, MtkWlanUserClient and `mtkwifi` tools. The MT7925 Connac3
backend stays separate. This is an experimental x86_64 macOS build.

The original MT7902 0.2.11 driver connected to Android and iPhone hotspots in user
testing. The 0.2.12 HT20 router compatibility changes and this new MtkWlan
integration have **not** been validated on hardware. A build passing CI does not
establish that your router will work.

## Install and connect

1. Keep your known-working EFI and hotspot-capable driver as a recovery copy.
2. Disable/remove `itlmt7902.kext` in OpenCore's Kernel/Add list. Replace it with
   this package's `MtkWlan.kext` in `EFI/OC/Kexts` and update the OpenCore entry:
   BundlePath `MtkWlan.kext`, ExecutablePath `Contents/MacOS/MtkWlan`,
   PlistPath `Contents/Info.plist`, Enabled true. Use your existing snapshot tool.
   Load exactly one driver for the PCI device. Do not add MtkWlanNative for this port.
3. Boot once to load the new kext. Connection mode is the integrated backend's
   default; `mt7902_stage=3` is unnecessary. Remove a previous stage 0/1/2 override
   if you have one. Existing non-stage diagnostic boot arguments still work.
4. Quit the old ItlWiFi7902 app and open **MtkWiFi7902.app** from this package.
   It uses MtkWlan's API, derives the WPA2 PMK in userspace and supports scan,
   password entry, join, disconnect and saved networks. Reconnects and further
   network changes do not require rebooting. Disable the old app's login item if set.
5. Alternatively, run `./mtkwifi status`, `sudo ./mtkwifi scan --wait`,
   `sudo ./mtkwifi join "Your SSID" --ask` or `sudo ./mtkwifi disconnect`.
   The password is requested at the terminal, not passed in a command argument.

The MT7902 personality explicitly permits the logged-in console user to scan,
join and disconnect, matching the old menu app. Set `MtkAllowConsoleControl` false
for administrator-only control. This does not change MT7925's administrator-only
policy. Tuning stays administrator-only and is unsupported on MT7902.

## Architecture and current limits

MtkWlan selects the backend using PCI 14c3:7902 before any MT7925 MMIO or DMA.
The Connac2 worker remains the sole owner of firmware commands, the supplicant,
and hardware rings. Bounded 64-packet RX/TX queues carry Ethernet frames across
to the Mtk work loop. Every Mtk frontend callback runs on that work loop's gate;
no worker callback enters the frontend while holding a backend lock. The Ethernet
interface starts only after the firmware's station MAC has been read.

Both chips' firmware is embedded in MtkWlan.kext. No external firmware folder is
required. CI checks the firmware checksums and verifies each complete blob occurs
exactly once in the final executable. Original license notices accompany the build.

MT7902 supports Mtk core API v1/v2 and userspace API v1. It refuses v3/v4/v5
instead of advertising unsupported native/private-MAC/country operations.
Stock HeliPort and the native macOS Wi-Fi menu are not compatible with this port.
Use the included MtkWiFi7902 app or mtkwifi.

Only visible WPA2-PSK/CCMP networks with optional PMF are joinable. No open, WEP,
WPA3-only, enterprise, required-PMF, explicit BSSID pinning, DFS or 6 GHz joins.
Supported join channels are 1–11, 36/40/44/48 and 149/153/157/161/165. Embedded-NUL
SSIDs and unsupported request types are rejected rather than altered. The backend
keeps the existing 10 dBm test ceiling, single-stream HT20/legacy profiles and
legacy fallback. Group rekey, sleep/wake and router interoperability remain
unfinished. Off-channel scans while connected are refused; disconnect to rescan.

Run `bash collect-logs.sh` after a failed attempt. It captures the MtkWlan service,
Ethernet interface and mirrored backend diagnostics. Hardware validation needs
scan, WPA2 handshake, DHCP, DNS, IPv4/IPv6 traffic, disconnect/rejoin and sustained
traffic on both the working hotspot and the router. No successful router test has
been claimed for this integration.
